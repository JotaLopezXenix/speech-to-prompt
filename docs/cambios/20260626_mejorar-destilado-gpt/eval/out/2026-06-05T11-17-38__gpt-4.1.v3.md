- Diagnóstico: Se duplican puntuaciones en scores. Se insertan filas nuevas aun cuando el ranking no ha variado.

### Problemas detectados
- La tabla scores crece de forma innecesaria con filas duplicadas (mismo ranking, misma puntuación).
- La pantalla de comparación presenta información reiterativa o irrelevante: columna "externo" y otras, muestran datos no pertinentes.

### Replanteamiento del modelo de datos

**Objeto central:**
- La foto es el elemento clave. Cada foto tiene un histórico de puntuaciones, manuales o automáticas, asociadas a ejecuciones y parámetros.

**Modelizado de las puntuaciones:**
1. Cada foto tiene siempre identificador único (por metadatos).
2. Las puntuaciones se guardan solo cuando hay cambios respecto a la última registrada.
3. Secuencia por foto:
    - Comprobar XMP: Si la puntuación del XMP es diferente a la última registrada, se actualiza en BD.
    - Lanzar evaluación automática: Si el resultado difiere de la última puntuación, se actualiza en BD.
    - Si no hay ningún cambio, no se inserta una fila en scores.
4. El histórico de scores solo guarda las puntuaciones nuevas, nunca repetidas.
5. El ranking actual corresponde al último ID autonumérico de scores para la foto.

**Escenarios típicos:**
- Procesar carpeta repetidamente sin cambios (parámetros ni puntuaciones externas): BD permanece estática.
- Tras puntuaciones manuales nuevas en Lightroom: la aplicación detecta el cambio y actualiza la puntuación antes de recalcular el ranking.
- El histórico evidencia todas las evaluaciones relevantes (manual + automático); para cada foto pueden coexistir varias puntuaciones.
